## Summary

The capture backend exposes **capture-link data retrieval without authentication** and issues
capture links with **sequential identifiers** generated by a global counter (~0 entropy).

## Technical detail

- The capture-link data retrieval endpoint responds without authentication (verified live).
- Link identifiers are issued by a **global sequential counter** (about 2 ids/s, ~0 entropy) —
  fully predictable.
- One-time link consumption is observable: used links are denied on retry (so enumeration
  distinguishes active vs consumed links).
- Link metadata exposes personal identifiers of the capture subject.

## Impact

A remote attacker can:
- enumerate the active link space (the counter window),
- retrieve the associated **identity-proofing capture data** before the one-time link is consumed,
- observe link consumption state — targeted access to in-flight onboarding captures.

## Reproduction

Retrieval tested without authentication against the production API; sequential counter behaviour
and one-time consumption confirmed.

## Recommendations

- Require authentication on the link retrieval endpoint.
- Issue unguessable link identifiers from a CSPRNG; bind links to the session/device that
  started the capture.
- Do not expose capture metadata without the subject's authenticated session.

## Timeline

- 2026-10-01 — SDK inventory and live validation
- 2026-10-29 — CVE requested from MITRE (CNA-LR); vendor notification in progress

## Evidence (deterministic)

- Link-data retrieval on the vendor document/liveness backend responds 200 without authentication.
- `id_link`: global sequential counter (~1.95 ids/s, 9-digit space, ~0 entropy, +1 per session).
- Retry after one-time consumption is denied.
